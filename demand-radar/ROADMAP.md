## 定位

开源、自托管的需求发现工具。同类项目（Reddit_Scrapper、pain-miner、sift 等）都在早期，没有一个同时做到：**全本地模型、一条命令部署、质量可量化**。这三点是我们的差异化，后续每一步都不能丢：不引入必须付费的 API，不增加部署步骤，每次改动都过评测。

市场调研的结论是需求真实、商业天花板有限，所以**先做出能发布的版本拿到真实反馈，再做重功能**。

## 现在在哪

已经能用：四类公开数据源 → 本地模型抽取 → MongoDB → Markdown 清单，`docker compose up` 一条命令部署，31 个离线测试。

质量基线：45 条人工标注的真实样本，`python -m demand_radar eval` 一键评测。qwen2.5:3b、温度 0 时 **F1 = 85.1%**（精确率 83.3%、召回率 87.0%），两次运行逐条一致。

## 里程碑

### v0.1：可以发布（约 1.5 周）

拿得出手，能放到社区让人试用，并能每周产出有价值的内容。

- [ ] 规则预过滤：明显的噪音和作品发布帖不再交给模型（误报里有一半可以这样挡掉，还能省下模型调用）
- [ ] 分项打分：痛点清晰度、表达强度、可实现性，解决「可信度都是 0.9」的问题
- [ ] 原文摘录：每条需求附一句原帖原话，程序校验确实来自原文
- [ ] 输出语言可配置
- [ ] 抽取失败也记录，超过 3 次不再重试
- [ ] 综合排序：分项打分 + 热度
- [ ] 每周摘要命令 `digest`：用来每周公开发布，同时验证有没有人关注
- [ ] 默认模型改成 3b；英文 README、LICENSE、CI；拆成独立仓库

验收：评测 F1 ≥ 85.1%，摘录有效率 ≥ 90%，规则零误杀；干净机器上 `docker compose up` 能出清单和摘要。

**发布后**：发到 HN、r/SaaS、Indie Hackers、V2EX，收集反馈，再决定 v0.2 的优先级。

### v0.2：持续积累（约 1.5 周）

跑一个月后，库里是几千条有效需求，而不是每天重复处理同样的内容。

- [x] 增量抓取：每个源记录上次抓到哪
- [x] 历史回填：softwarerecs 有 2.3 万条、HN 关键词能命中上万条，分批拉，可中断续跑（`backfill --source … --pages N`）
- [x] 并发调用模型（`--workers`，默认 2；纯 CPU + Ollama 默认串行时提升有限，待真机实测）
- [x] 运行记录：每次运行的抓取数、过滤数、失败数、耗时
- [ ] 定时运行：每天抓取，每周出摘要
- [ ] 实测 Arctic Shift 作为 Reddit 数据源（可能同时解决限流和历史数据问题）

验收：连续运行一周不重复处理；回填能中断续跑。

### v0.3：合并与看板（约 2 周）

- [ ] 相似需求合并：本地 embedding 模型向量化，先用相似度阈值，不够再上 UMAP + HDBSCAN
- [ ] Web 看板：FastAPI + 静态页，按领域、时间、排序分筛选
- [ ] 「已有方案」提示：优先评估集成现有的 idea-validation 开源项目

验收：同一需求在多个来源出现只显示一条，标明来源数和总热度。

### 穿插进行

**真机验证**（需要你在自己电脑上操作，我的沙箱加了代理和证书，复现不了普通电脑的环境）：
- [ ] 原样执行 `docker compose up`，把第一次运行的问题贴给我修
- [ ] 验证 GitHub 源（沙箱只能访问当前仓库，GitHub 源只有单元测试）
- [ ] 看看你的机器上每条要几秒，决定默认模型

**验证价值**（同类项目都没做到，是整个方向最大的不确定性）：
- [ ] 自己从清单里挑一个点子真正做出来，记录从发现到上线的过程

**社区连接**：
- [ ] 发布后联系 pain-miner、sift 等项目作者，看能否互相集成

## 模型选择

测试阶段默认 **qwen2.5:3b**。纯 CPU 沙箱、45 条评测的对比：

| 模型 | 45 条耗时 | F1 | 结论 |
|---|---|---|---|
| qwen2.5:3b | 390 秒 | 85.1% | 默认 |
| qwen2.5:1.5b | 198 秒 | 78.0% | 低配机器备选 |
| qwen2.5:0.5b | 103 秒 | 0% | 不可用 |
| qwen3:1.7b | 每条 30 多秒 | — | 默认开启思考模式，比 3b 还慢，不推荐 |
| llama3.2:1b、gemma3:1b | 测试中 | | |

## 需要你决定

1. 开源协议：建议 MIT
2. 输出语言：默认中文，还是跟原帖语言一致（面向海外社区发布可能需要英文）
3. 独立仓库的名字

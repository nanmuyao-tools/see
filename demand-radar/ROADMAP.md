# 需求雷达：路线图

更新：2026-10-19。方案见 [`../docs/ideas/demand-radar.md`](../docs/ideas/demand-radar.md)，技术选型与实测记录见 [`../docs/ideas/demand-radar-tech.md`](../docs/ideas/demand-radar-tech.md)。

## 现在在哪

已经能用：四类公开数据源 → 本地模型抽取 → MongoDB → Markdown 清单，`docker compose up` 一条命令部署，23 个离线测试。用真实数据跑过：40 条原始内容产出 19 条需求，其中约 15 条是真需求。

还没做到的：清单质量不够稳（混入作品发布帖、语言不统一、可信度没有区分度）；每次只抓最新几条，没有历史回填；相似需求不会合并；只有 Markdown 没有看板；GitHub 源和 7b 模型没在真实环境验证过。

## 阶段划分

每个阶段结束都有一个「能看到的东西」。先后顺序是按风险排的：先确认在真实机器上能跑，再提质量，再加功能，最后对外发布。

### 阶段 1：在用户自己的机器上跑通（1–2 天）

目标：不是在我的沙箱里，而是在一台普通电脑上，`docker compose up` 出一份清单。

- [ ] 在本地电脑原样执行 `docker compose up`，记录第一次运行遇到的所有问题并修掉
- [ ] 验证 GitHub 源（沙箱访问不了，只有单元测试）
- [ ] 用默认的 7b 模型跑一轮，和 3b 对比清单质量与耗时，决定默认值
- [ ] 把 `main` 分支更新到当前进度

验收：一台没装过 Python、MongoDB、Ollama 的机器，按 README 操作能拿到 `out/demands.md`。

### 阶段 2：让清单可信（1 周）

目标：19 条里有 15 条可用 → 20 条里有 18 条可用，并且这个数字是量出来的，不是感觉。

- [ ] 把评测集放进仓库：目前 14 条带标准答案的真实样本，扩充到 40–50 条，覆盖各个源
- [ ] 加 `eval` 命令：跑一遍评测集，输出判对率；以后每次改 prompt 都先跑它
- [ ] 过滤「供给」帖：Show HN、「我做了一个」这类是作品发布，不是需求
- [ ] 输出语言统一：要么全中文，要么保留原文语言，不要混着来
- [ ] 可信度要有区分度：现在几乎全是 0.9，考虑让模型按「多少人会要」「原帖是否明确表达需要」分项打分再合成
- [ ] 清单里附一句原文摘录，方便人工快速核对模型有没有概括偏

验收：评测集判对率 ≥ 85%，且清单每条都能靠摘录一眼判断对不对。

### 阶段 3：从「抓最新几条」到「持续积累」（1 周）

目标：跑一个月之后，库里是几千条去过重、合并过的需求，而不是每天重复的 40 条。

- [ ] 每个源记录抓取游标（时间或 id），只抓增量
- [ ] 历史回填：softwarerecs 有 2.3 万条、HN 关键词有上万条，按限额分批拉
- [ ] 相似需求合并：用 embedding 聚类，把不同来源说的同一件事归到一起，合并后的热度 = 各来源热度之和
- [ ] 定时运行：compose 里加一个按天跑的调度，或者在 README 里给 cron 示例

验收：同一需求在不同来源出现，清单里只有一条，并标明来自几个地方、共多少人提过。

### 阶段 4：让人用起来（1 周）

目标：不用看 Markdown，打开网页就能按领域、热度、时间筛选。

- [ ] 一个轻量 Web 看板（后端出 JSON，前端静态页即可）：按领域筛、按热度排、看原帖
- [ ] 「已有方案」提示：抽出需求后，顺手查 Product Hunt、小众软件等供给源，标注「可能已有人做了」
- [ ] 每周摘要：本周新增的高分需求，输出一份 Markdown，方便发到社区

验收：自己每周看一次看板，能挑出 1–2 个想做的点子。

### 阶段 5：开源发布（视前面进度）

- [ ] 拆成独立仓库，补英文 README、License、贡献指南
- [ ] CI 跑单元测试和评测集
- [ ] 第一个 Release，写清楚「它能做什么、不能做什么、数据从哪来、怎么合规」
- [ ] 发到 HN / V2EX / r/SomebodyMakeThis 收反馈。本身就是在用它找到的渠道推广它

## 待定事项（想到了，但不急）

- 更多数据源：App Store 低分评论（吐槽类）、Product Hunt 评论、V2EX 按关键词过滤；中文源可以考虑自部署 RSSHub，但要先看清各平台的服务条款
- 云模型选项：没有好机器的用户可以填一个 API key，用云模型跑
- 多语言：需求原文是英文的，要不要翻译后再抽取，看评测结果决定
- 把这个项目和 `see` 仓库里另外两个想法（短视频时长统计、Mac 截图工具）分开管理

## 先做什么

**阶段 1 的第一项。** 现在最大的不确定不是功能，而是「它在别人电脑上到底能不能一把跑起来」。这一步需要你在自己机器上实际运行一次，因为我的沙箱环境加了代理和证书，没法复现一台普通电脑的真实情况。你跑的时候把报错贴给我，我来修。

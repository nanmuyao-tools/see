# 更多可能性：不改网络、不买设备

前面的方案（见 [traffic-access.md](traffic-access.md)）都需要让流量**经过**一台我们能控制的设备。这里换两个角度：

1. **直接问原厂路由器要数据**：它自己就知道每台设备的实时网速。
2. **在空中旁听 Wi-Fi**：不接入网络，被动接收无线帧。

两者都可以和[按流量形状识别视频](behavior-detection.md)结合：只要拿到"每台设备的下行速率时间序列"，就能判断是不是在看视频。

## 1. 读取原厂路由器的"每设备实时网速"（重点推荐）

很多原厂路由器的管理页面和 App 上，能看到每台设备当前的上传、下载速度。这些数据来自路由器的本地接口，我们可以写个脚本定时去读。

| 品牌 | 现成的轮子 | 能拿到的数据 |
|---|---|---|
| 小米 | [pymiwifi](https://pypi.org/project/pymiwifi)（`misystem/status` 接口）、[hass-miwifi](https://github.com/dmamontov/hass-miwifi/blob/d5a2a2b3017ed403a151233ed94a939389c6177d/README.md)（Home Assistant 集成，走 LuCI API，不需要 ssh） | 每台设备的 `upspeed` 和 `downspeed`，单位要实测确认 |
| 华为 | [huawei_mesh_router](https://github.com/vmakeev/huawei_mesh_router)（Home Assistant 自定义组件） | 每台设备的上传/下载速率、频段、信号强度；支持 Wi-Fi 访问控制 |
| 其他品牌 | 大多有类似的网页接口，需要逐个研究 | — |

```
原厂路由器（不改）◀── 每 5–10 秒读一次接口 ── 脚本（跑在旧手机的 Termux / 电脑 / NAS 上）
                                              │
                                              ▼
                     每台设备的下行速率序列 → 判断是否在看视频 → 时长、报表
                                              │
                                              └─ 超时后通过路由器接口把这台设备拉黑或断网（可选）
```

**优点**：

- **零硬件**：脚本可以跑在家里任何常开的设备上。旧 Android 手机装 Termux 就行，**不需要 root**，因为只是发 HTTP 请求。
- **零网络改动**：手机正常连原来的 Wi-Fi，什么都不用设置，也没有单点故障。
- **正好符合最初的设想**：直接利用家里现有的路由器。

**局限与风险**：

- **采样粗**：路由器给的是某一时刻的瞬时速率，每 5–10 秒读一次，短促的突发可能漏掉。按分钟判断"在不在看视频"大概够用，但要区分短视频和长视频就比较难。hass-miwifi 建议轮询间隔不要低于 10 秒，更快的轮询可能给路由器增加负担。
- **每个品牌、每个型号的接口都不一样**，固件升级后也可能变。只能先支持家里这一台。
- **识别不出是哪个 App**，只能判断"在看视频"。
- 原厂路由器通常会开启硬件加速，网速统计是否准确要实测。

**验证方法**：一边刷抖音，一边用 pymiwifi 每 5 秒读一次手机的 `downspeed`，然后画曲线，和刷网页、待机时的曲线对比。

## 2. 在空中旁听 Wi-Fi（被动嗅探）

Wi-Fi 是无线广播，任何设备都能"听到"空中的无线帧。WPA2/WPA3 加密的只是帧里的数据内容，**帧头仍然是明文**：

- 发送方和接收方的 MAC 地址，能知道是哪台手机；
- 帧的长度和时间，能知道流量大小和节奏；
- 传输方向，是路由器发给手机，还是手机发给路由器。

这正好是"按形状识别视频"需要的全部信息。研究上也证明过可行：[Deep Content (2018)](https://opus.cloud1.lib.uts.edu.au/handle/10453/128553) 在不接入网络的情况下，只靠旁听 Wi-Fi 帧就能识别出正在播放的是哪个 YouTube 视频。我们只需要判断"是否在看视频"，要求低得多。

| 硬件 | 价格 | 说明 |
|---|---|---|
| ESP32 开发板 | 约 20 元 | 支持混杂模式，只支持 2.4GHz，单天线 |
| ESP32-C5 | 几十元 | 支持 2.4 和 5GHz 双频，[官方文档](https://docs.espressif.com/projects/esp-idf/en/latest/esp32c5/api-guides/wifi-driver/wifi-modes.html)说明可以抓数据帧，包括 AMPDU 和 MIMO；有用户反馈 5GHz 下帧类型报告有 bug |
| 支持监听模式的 USB 无线网卡 + Linux 电脑 | 几十到一百多元 | 最稳妥，可以用 Wireshark/tcpdump 直接分析 |

**优点**：

- **完全不碰网络**：和路由器品牌、配置都无关。
- 数据粒度比路由器接口细得多，精确到每一帧。

**局限与风险**：

- **信道**：路由器要固定信道，否则自动换信道后就听不到了；路由器的双频合一（band steering）会让手机在 2.4G 和 5G 之间切换。
- **解码能力**：手机一般是 2×2 MIMO，速率很高；单天线的 ESP32 可能解不出这些数据帧，这是最大的不确定点。用 2×2 的 USB 网卡会好很多。
- **重传和聚合帧**会让统计出现偏差（论文里也提到了）。
- **只能看，不能管**：没法拦截。
- **合规**：只分析自己家的设备，按 MAC 过滤，不要记录邻居的数据。

## 3. 其他想过但不推荐的

| 想法 | 不推荐的原因 |
|---|---|
| 读光猫管理页面 | 路由器下面的设备经过 NAT 后，光猫只能看到路由器这一台设备 |
| 在运营商侧统计 | 拿不到数据 |
| 手机屏幕录制 + 识别画面 | 耗电，隐私问题大；不如直接用系统的屏幕使用时间 |

## 对比与建议

| 方案 | 成本 | 改动网络 | 数据粒度 | 能拦截 | 主要风险 |
|---|---|---|---|---|---|
| **读路由器接口** | 0（旧手机 / 电脑跑脚本） | 不改 | 粗（每 5–10 秒一次瞬时速率） | ✓（部分型号能拉黑设备） | 采样太粗、接口因品牌而异 |
| Wi-Fi 嗅探 | 20–100 元 | 不改 | 细（每一帧） | ✗ | 解码能力、信道、双频切换 |
| 旁路网关 | 0–100 元 | 改手机网关 | 细（每个包） | ✓ | 要折腾，盒子是单点 |

**建议**：

1. 如果家里路由器是小米或华为，**先试"读路由器接口"**。零成本、零改动，半天就能验证。
2. 如果采样太粗，判断不准，再考虑 Wi-Fi 嗅探（想要不碰网络的话）或旁路网关（想要能拦截的话）。

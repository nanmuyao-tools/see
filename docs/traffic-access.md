# 让流量经过"我们能控制的网卡"：接入方式对比

前提：原厂路由器（华为、小米等）**没法在上面加虚拟网卡或装程序**。不过这个想法的本质是：

> 让手机的流量经过一个我们能运行程序的网卡（真实的或虚拟的），在那里统计和分析。

这块网卡不一定非要在路由器上。按它放在哪里，可以分成下面几种方案。

## 方案总览

| # | 方案 | 网卡在哪 | 额外硬件 | 改动原路由器 | 能区分设备 | 4G 能否统计 | 推荐度 |
|---|---|---|---|---|---|---|---|
| 1 | **旁路网关（旁路由）** | 小盒子 / 电脑的网卡 | 盒子（约 100–300 元）或旧电脑 | 不改；只改手机的网关设置 | ✓ | ✗ | ★★★★★ |
| 2 | **原路由器改 AP 模式，软路由做主路由** | 软路由盒子 | 软路由盒子 | 切到"AP / 有线中继"模式 | ✓ | ✗ | ★★★★ |
| 3 | 电脑开热点 | 电脑的虚拟 AP 网卡 | 无 | 不改 | ✓ | ✗ | ★★★（适合做实验） |
| 4 | 手机 VPN（TUN 虚拟网卡）回家 | 家里盒子上的 WireGuard 接口 | 盒子 | 不改，可能要做端口映射 | ✓ | **✓** | ★★★ |
| 5 | 手机本地 VPN（Android VpnService） | 手机自己的 TUN 网卡 | 无 | 不改 | 能区分到**具体 App** | ✓ | ★★★（其实就是手机端方案） |
| 6 | 原路由器开 VPN 客户端，连到云服务器 | 路由器的隧道接口 → 云服务器 | 云服务器 | 设置 VPN | ✗（经过 NAT 后都是同一个 IP） | ✗ | ★ |
| 7 | 交换机端口镜像 | 镜像口接分析盒子 | 网管交换机 + 盒子 | 不改 | ✗（IPv4 经过 NAT 后都是同一个 IP） | ✗ | ★ |

## 1. 旁路网关（重点推荐）

```
                 ┌──────────── 原路由器（任何品牌，不改）────────── 光猫 ── 互联网
手机 ─ Wi-Fi ───┤                      ▲
  (网关 = 盒子)  └─▶ 盒子 (OpenWrt/Linux) ┘
                    在这里统计、分析
```

- **做法**：盒子用网线接在原路由器上，开启转发和 NAT。在手机的 Wi-Fi 设置里改成静态 IP，**把网关和 DNS 填成盒子的地址**。
- **只影响这一部手机**：家里其他设备照常走原路由器。盒子坏了，只要把手机改回 DHCP 就恢复了。
- **跟路由器品牌无关**，正好解决"家里路由器什么牌子都有"的问题。
- **硬件选择**：
  - 二手小盒子刷 Armbian/OpenWrt，比如斐讯 N1 这一类，约 100 元；
  - 树莓派；
  - x86 小主机；
  - 一台常开的旧电脑。
- **注意**：
  - 盒子上要做 MASQUERADE（NAT）。否则回程流量会直接从原路由器发给手机，绕过盒子，盒子只能看到上行（不对称路由）。
  - 要让全家设备都走盒子，就得关掉原路由器的 DHCP，改由盒子分配地址，而且网关下发的是盒子。很多原厂固件不允许改 DHCP 下发的网关，所以只能这样替换。
  - Wi-Fi 下的流量会经过"手机 → 路由器 → 盒子 → 路由器 → 光猫"，同一根网线来回各走一次。家用百兆到千兆宽带一般没问题。

## 2. 原路由器改 AP 模式，软路由盒子做主路由

```
光猫 ── 软路由盒子 (OpenWrt，负责拨号/NAT/DHCP/统计) ── 原路由器 (AP 模式，只负责 Wi-Fi) ── 全家设备
```

- **适合**：想管全家设备的情况。华为、小米的原厂固件基本都支持 AP 或有线中继模式。
- **好处**：全家流量都经过盒子，没有不对称路由的问题，原来的 Wi-Fi 覆盖也保留了。
- **代价**：盒子成了全家上网的关键，挂了全家断网；拨号等配置也要迁到盒子上。

## 3. 电脑开热点（最适合做验证实验）

- Windows 自带"移动热点"，Linux 用 hostapd 或 NetworkManager，macOS 用"互联网共享"。电脑上会多出一块虚拟 AP 网卡。
- 手机连上电脑的热点，在电脑上用 Wireshark/tshark 抓包，就能完成[可行性实验](feasibility.md#6-第一步低成本验证实验不用买硬件)。
- 不适合长期使用：电脑要一直开着。

## 4. 手机 VPN 回家（唯一能覆盖 4G 的网络层方案）

- 家里的盒子跑 WireGuard 服务端，手机装 WireGuard 客户端，并设置"始终开启 VPN"。手机的流量不管走 Wi-Fi 还是 4G，都先进 TUN 虚拟网卡，再回到家里盒子分析，最后出网。
- **要求**：家里宽带有公网 IPv4，或者能用 IPv6 / DDNS。如果没有公网地址，只能中转，成本会增加。
- **代价**：在外面用 4G 时，流量要绕回家，受家里上行带宽限制，比如 30–50 Mbps，刷视频可能卡顿。
- 可以只在 Wi-Fi 下用（这时本来就在家里），在外面关掉。

## 5. 手机本地 VPN（Android VpnService）

- 系统给 App 一块 TUN 虚拟网卡，所有流量都先经过 App 里的程序。系统还能告诉程序**每个连接属于哪个 App**（UID），开源项目 NetGuard 就是这么做的。
- 这本质上就是"手机端方案"。既然系统直接知道是哪个 App，也就不需要做流量识别了。
- iOS 不行：iOS 的 VPN 拿不到每个连接属于哪个 App。

## 6/7. 不推荐的两种

- **原路由器 VPN 客户端连云服务器**：部分原厂固件支持 L2TP/PPTP 客户端，可以把全家流量导到云服务器上分析。但 IPv4 经过 NAT 后都是路由器的地址，分不清设备；视频流量走云服务器的带宽，又贵又慢。
- **端口镜像**：在光猫和路由器之间放一台网管交换机，把流量镜像到分析盒子。但此时 IPv4 流量已经被路由器做过 NAT，**分不清是哪台设备**。IPv6 没有 NAT，倒是能按地址区分设备，但覆盖不全。

## 结论

| 场景 | 推荐 |
|---|---|
| 先验证可行性 | 方案 3：电脑开热点抓包，零成本 |
| 只统计自己的手机 | **方案 1：旁路网关**，只改手机的网关设置，零风险，跟路由器品牌无关 |
| 管全家设备 | 方案 2：软路由当主路由，原路由器改 AP 模式 |
| 还想统计 4G | 方案 4：WireGuard 回家，或者直接用手机端方案 |

不管用哪种接入方式，后面的分析程序都可以是同一套：按流量形状识别视频，再按域名标注 App。分析程序跑在"那块网卡"所在的 Linux 设备上即可。

# see：看见自己刷了多久短视频

> 在家庭网络这一层，统计每台设备刷短视频（抖音、快手、B站、视频号、小红书）的时长，必要时加以限制。

## 缘起

我发现自己有些沉迷短视频。手机自带的"屏幕使用时间"能统计时长，但限额一到，点一下"再用 15 分钟"就继续刷了，几乎没有约束力。

于是有了这个想法：**不在手机上装任何东西，直接从家里的网络流量里统计出刷短视频的时长。** 理由有三条：

- **绕不过**：只要连着家里的网络，统计和规则就一直有效，不依赖某台设备上的设置；
- **管得全**：手机、平板、电视等多台设备一起统计；
- **能干预**：超过额度或到了深夜，直接在网络层断开视频流量。这种摩擦比手机上的弹窗大得多。

另外，这也是一个学习网络流量分析的好项目。

## 核心思路

流量都是加密的，网络上看不到具体在看哪条视频。但有两类信号藏不住：

1. **流量的"形状"**：看视频时下行持续偏高，上行很少，流量一阵一阵地突发。短视频每划一下就来一次几 MB 的突发，间隔不规则；长视频则是按节奏规律地下载分片。
   **只看形状就能判断"是不是在看视频"**，不用管是哪个 App，也不怕加密、QUIC、HTTPDNS 或私有协议。
2. **域名**：TLS/QUIC 握手中的 SNI，以及 DNS 查询，能顺带标出是哪个 App。这一类信号只是锦上添花，不是必需的。

```
每台设备的流量时间序列（每 5–10 秒：上下行字节数、包数）
   → 每分钟判定"是否在看视频"（下行 ≥ 阈值、下行远大于上行、不是长时间跑满带宽）
   → 合并会话（空闲 ≤ 2 分钟算同一次）
   → 每日时长、报表、超额提醒或拦截
   （能拿到 SNI 或 DNS 时，顺手标上 App 名）
```

## 流量从哪里来

家里的原厂路由器（华为、小米等）是封闭系统，装不了程序。所以关键在于**让流量经过一个我们能运行程序的网卡**：

| 方式 | 成本 | 覆盖范围 |
|---|---|---|
| **定时读原厂路由器的"每设备实时网速"接口**（小米、华为有现成的库） | 0 元，网络不用改 | 全家设备，只是采样比较粗 |
| 电脑开热点抓包 | 0 元 | 做验证实验 |
| 手机上用 PCAPdroid（Android 本地 VPN） | 0 元 | 只覆盖本机，4G 也能统计 |
| 二手玩客云 / 斐讯 N1 做**旁路网关**（只把手机的网关指向它） | 30–100 元 | 只覆盖自己的手机，和路由器品牌无关 |
| 能刷 OpenWrt 的路由器做主路由，原路由器改 AP 模式 | 约 150 元 | 全家设备 |

## 现状与结论

- **技术上可行**：识别、统计、存储都有成熟的开源做法可以借鉴，比如 OpenAppFilter、nDPI、netifyd、nlbwmon、AdGuard Home。
- **没有现成的轮子**：手机端已有很多工具（系统屏幕使用时间、one sec、ScreenZen、Mindful 等），路由器端有商业产品 Firewalla，但**面向国内 App、在网络层统计短视频时长的开源方案目前还是空白**。
- **最大的不确定性**：仅凭流量形状，"是否在看视频"能判断得多准，和长视频、直播、下载能不能区分开。要用抓包实验来验证。
- **如果只是想少刷**：零成本的组合已经够用。手机屏幕使用时间 + 路由器家长控制（晚上断网）+ one sec 或 ScreenZen（打开前强制停顿）。

## 路线图

- [x] 方案讨论与开源项目调研
- [ ] **验证实验**：电脑开热点或用 PCAPdroid，录下刷短视频、看长视频、聊天、下载、视频通话各 10–15 分钟的流量，验证按形状识别的准确率（目标：分钟级 ≥ 90%）
- [ ] 抓包分析脚本：输入 pcap，输出流量曲线和逐分钟判定结果
- [ ] v0：在旁路网关上用 conntrack 采集计数，做分钟统计和会话合并，存 SQLite，加一个简单网页
- [ ] v1：提取 SNI 和 DNS，标注 App
- [ ] v2：超额拦截、日报推送
